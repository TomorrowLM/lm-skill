# 阅读类场景 token 优化

## 文件阅读

目标是找到影响决策的代码/配置，不是读完整个文件。

**步骤：**

1. 先看目录结构或文件名，判断哪个文件可能包含目标信息。
2. 用关键词在该文件中搜索，定位到相关行段。
3. 只读取包含目标逻辑的行段（前后各留 3-5 行上下文），不读完整文件。
4. 够用就停——一个文件不需要读第二遍，除非第一遍漏了关键信息。

**不做的：**

- 不连续小段反复读同一个文件，合并为一次大段读取。
- 不因为"可能有其他相关代码"而读相邻文件；先确认当前文件无法满足需求。
- 不在多项目 workspace 中扫描所有项目的同名文件。

## 用户重复粘贴/附加同一文件

判定条件：当前请求附带的文件内容，与本会话之前已读取/附加过的同一文件（路径相同）重复。

**动作：**

1. 不要把整份重复内容当新信息处理，也不要在回复中再次转述或摘录全文。
2. 直接使用工具（`read_file`）按需读取该文件当前版本的目标行段，忽略用户粘贴的重复正文。
3. 只在文件确实发生变化、且用户粘贴内容与工具读取结果不一致时，才以工具读取结果为准。
4. 回复中提醒用户下次可以只说"继续用刚才的 xxx，只看某函数/某行"或"重新读取 xxx 当前版本"，不需要再贴全文。

**不做的：**

- 不因为"命中了提示缓存"就认为重复粘贴没有代价——缓存只降低处理成本和延迟，不减少上下文窗口占用。
- 不假设客户端会自动为重复附件去重，按会增加处理。
- 不在同一文件连续多轮里反复要求或接受用户重新粘贴全文。

## 大仓库代码探索

**步骤：**

1. 先目录搜索和符号搜索，再读入口文件或关键模块。
2. 优先用 `list_dir` 看结构，用 `grep_search` 定位关键词，用 `file_search` 找关键文件。
3. 必要时派只读子代理（Explore agent）返回路径和结论，不把探索过程带回主对话。

**常见陷阱：**

- 先 `read_file` 再判断是否相关——应该反过来。
- 为了"全面了解"打开 10+ 个文件后才开始改代码。

## 网页调研

**步骤：**

1. 先确认权威来源和发布日期，判断信息是否有效。
2. 只摘取与当前决策直接相关的事实，保留来源链接。
3. 不把整篇网页内容粘贴到对话中。

**不做的：**

- 不读取多个同主题网页来"交叉验证"——除非用户明确要求。
- 不摘录"可能有用"的背景信息。

## 接口文档（Swagger / OpenAPI）

**步骤：**

1. 只查目标 tag、operationId 或模型名，不加载整份接口文档。
2. 用 `get_swagger_mcp` 时优先指定 `operationId` 或 `tag` 精确查询。
3. 只保留请求参数、响应字段、类型定义等影响代码的事实。

**常见陷阱：**

- 加载整个 Swagger 文档"以防万一需要其他接口"。
- 重复查询同一个接口（先确认缓存是否已有）。

## Figma / UI 还原

**步骤：**

1. 先读取节点结构（层级、命名、分组），再读取截图获取视觉摘要。
2. 只下载当前步骤需要的资产，不预下载全部。
3. 不描述每个无关图层——只提取影响实现的样式、尺寸、间距。

**常见陷阱：**

- 逐层描述 Figma 中所有节点，包括装饰性图层。
- 为"以后可能用到"预下载全部图标和图片。
