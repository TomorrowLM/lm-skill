# 协作类场景 token 优化

## 多代理协作

**原则：** 子代理只返回决策所需的最小信息，不返回完整过程。

**给子代理的固定输出格式：**

- 结论：一句话总结
- 证据：文件路径、关键代码片段、搜索结果
- 风险：可能出错或不确定的点
- 建议：下一步行动

**禁止子代理返回：**

- 完整对话过程、搜索步骤、读取的文件列表
- 大段原文（除非是必须引用的精确文本）
- "我搜索了 X，然后读取了 Y，发现 Z" 的叙事

**主对话中：**

- 收到子代理结果后，只摘取决策相关部分，不全文转发。
- 多个子代理结果先合并摘要，再呈现给用户。

## 长对话续接

当对话已经很长，需要继续推进但保留关键事实时：

**步骤：**

1. 先写 5 类事实摘要，替代之前所有上下文：

| 类型 | 记录内容 |
|---|---|
| 目标 | 用户真正要达成什么 |
| 决策 | 已确认的方案、边界和取舍 |
| 证据 | 文件路径、命令结果、来源链接 |
| 风险 | 仍不确定或可能出错的点 |
| 下一步 | 只保留马上要做的 1-3 个动作 |

2. 之后只基于摘要推进，不再引用原始材料（除非需要精确文本）。
3. 压缩后不要重复粘贴原始材料。

**常见陷阱：**

- 每次回复都引用 10 轮之前的原文。
- 摘要里写了"读取了 fileA.ts"，实际只需要"fileA.ts 第 42 行定义了 X 接口"。
