# 协作类场景 token 优化

## 多代理协作

**原则：** 子代理只返回决策所需的最小信息，不返回完整过程。

**给子代理的固定输出格式：**

- 结论：一句话总结
- 证据：文件路径、关键代码片段、搜索结果
- 风险：可能出错或不确定的点
- 建议：下一步行动

**禁止子代理返回：**

- 完整对话过程、搜索步骤、读取的文件列表
- 大段原文（除非是必须引用的精确文本）
- "我搜索了 X，然后读取了 Y，发现 Z" 的叙事

**主对话中：**

- 收到子代理结果后，只摘取决策相关部分，不全文转发。
- 多个子代理结果先合并摘要，再呈现给用户。
- 委派机械性、低风险的子任务（格式转换、批量检索、简单分类）时，优先选轻量模型的子代理；涉及关键决策或复杂推理的子任务仍用主模型，避免小模型误判导致返工。

## 长对话续接

当对话已经很长，需要继续推进但保留关键事实时：

**步骤：**

1. 先写 5 类事实摘要，替代之前所有上下文：

| 类型 | 记录内容 |
|---|---|
| 目标 | 用户真正要达成什么 |
| 决策 | 已确认的方案、边界和取舍 |
| 证据 | 文件路径、命令结果、来源链接 |
| 风险 | 仍不确定或可能出错的点 |
| 下一步 | 只保留马上要做的 1-3 个动作 |

2. 之后只基于摘要推进，不再引用原始材料（除非需要精确文本）。
3. 压缩后不要重复粘贴原始材料。

**常见陷阱：**

- 每次回复都引用 10 轮之前的原文。
- 摘要里写了"读取了 fileA.ts"，实际只需要"fileA.ts 第 42 行定义了 X 接口"。
- 压缩摘要开头放时间戳、计数等易变信息，导致后续复用这段摘要时无法精确前缀匹配、白白损失缓存命中。固定不变的内容放前面，易变信息放最后。

## 分阶段会话与记忆快照

当任务规模大到一个会话装不下（例如"分析需求 → 出方案 → 落地实现"这种多阶段任务）时，不要在同一个会话里把全部历史一直往后带。

**步骤：**

1. 把任务拆成明确的阶段：分析、规划、执行（或更贴合任务的划分）。
2. 每个阶段结束时只产出一份结构化摘要（复用上面的 5 类事实格式），作为下一阶段的唯一输入。
3. 进入下一阶段时，不重新粘贴上一阶段的完整对话或原始材料，只带这份摘要；需要精确引用时才回头查具体文件或记录。
4. 如果宿主支持持久化记忆（如 memory 工具），把跨会话仍要用到的关键事实写成记忆快照落盘，而不是指望下次会话从头重新摸索或在上下文里反复重复。

**常见陷阱：**

- 一个会话里塞下"需求分析 + 方案设计 + 代码实现 + 测试"全流程，导致上下文越滚越大。
- 阶段之间重复转述前一阶段的完整过程，而不是只传结论性摘要。

## 上下文管理工具边界

- `/compact` 是宿主（Copilot Chat）处理的内置斜杠命令，Skill 或模型都无法调用；上下文过大时只能提醒用户手动执行，不要声称已经执行：

  > 当前阶段已完成，建议运行 `/compact focus on completed work, key decisions, changed files, verification results, and remaining tasks`。

- SKILL.md frontmatter 的 `context: fork` + `github.copilot.chat.skillTool.enabled`，**并不是真正的子智能体隔离入口**；经实测（2026-08-29）在当前 VS Code Copilot Chat 版本中通过 `skill` 工具调用时**未观察到隔离效果**——技能全文仍直接注入主会话上下文，不要把它当成 `runSubagent` 的替代方案，也不要依赖它来控制上下文占用。
- Skill 本身需要读取大量文件（如大规模代码审查）时，优先用子代理（`runSubagent`）承载读取和探索，只把压缩后的结果带回主会话；真正的隔离能力应由子代理执行路径提供，而不是依赖 Skill frontmatter。
