# Token Saving

## 核心目标

把上下文当作预算管理：先确定问题边界，再按证据逐层加载信息，只保留会影响下一步决策的内容。

## 先判定是否需要本技能

满足任一条件就使用：

- 需要阅读 3 个以上文件、网页、日志或接口文档。
- 工具输出可能超过 200 行。
- 任务跨越多个阶段、多个窗口或多个子代理。
- 用户要求总结、压缩、减少 token、节省上下文或避免污染会话。
- 任务需要写技能、改技能、测试技能、写代码、思考方案或访问多份文件。
- 任务涉及多项目 workspace、规范模板拼装、AGENTS/CLAUDE 文档同步或公共资源复用判断。
- 当前对话已经很长，需要继续推进但保留关键事实。

不适用：单句问答、简单计算、单文件小修、用户明确要求完整逐字输出。

## 工作流

### 1. 先设 token 预算

开始前用一句话写清：

- 当前目标是什么。
- 必须保真的信息是什么。
- 可以压缩或丢弃的信息是什么。

如果目标不清，先问一个选择题，不要先读大量材料。

### 2. 分层获取上下文

按这个顺序拿信息，够用就停：

1. 文件名、目录结构、标题、目录、摘要。
2. 当前项目已有清单、索引、AGENTS/README 中的约束摘要。
3. 精确搜索命中的片段。
4. 相关文件的大段读取。
5. 只有在必要时读取完整文件或完整网页。

避免“先全量读再筛选”。每次读之前说明它要验证哪个假设。

### 3. 控制工具输出

- 搜索时优先用具体关键词、路径范围和结果上限。
- 读文件时按章节或相关行段读取，不连续小段不要反复读。
- 多项目 workspace 中只读取当前上下文明确涉及的项目；不要为了“保险”扫描全部项目。
- 终端命令用项目脚本验证，不打印无关依赖树、完整构建日志或完整锁文件。
- 网页资料只摘取与当前决策有关的事实，保留来源链接。
- 日志分析先定位错误关键词、时间点和堆栈顶部，再扩展上下文。

### 4. 压缩并替换上下文

每完成一个阶段，立即把上下文压缩成 5 类事实：

| 类型 | 记录内容 |
|---|---|
| 目标 | 用户真正要达成什么 |
| 决策 | 已确认的方案、边界和取舍 |
| 证据 | 文件路径、命令结果、来源链接 |
| 风险 | 仍不确定或可能出错的点 |
| 下一步 | 只保留马上要做的 1-3 个动作 |

压缩后不要再重复粘贴原始材料，除非用户要求或需要引用精确文本。

### 5. 按场景读取对应 reference

判断当前任务属于哪个场景，读取对应的 reference 文件获取详细指引。不预加载所有 reference。

| 场景 | 读取文件 | 说明 |
|---|---|---|
| 文件阅读、代码探索、网页调研、接口文档、Figma/UI 还原 | `references/reading.md` | 阅读类场景 |
| 写技能、改技能、测试技能、写代码、思考方案 | `references/writing.md` | 产出类场景 |
| 多代理协作、长对话续接 | `references/collaboration.md` | 协作类场景 |
| 构建/测试失败、日志分析、PR/Diff 审查 | `references/debugging.md` | 调试与审查类场景 |
| AGENTS/规范模板生成、公共组件复用、多项目 workspace | `references/project-setup.md` | 项目配置类场景 |

读取时只读与当前场景直接相关的章节，不读整个 reference 文件。

### 6. 回复要短，但不能少证据

默认输出结构：

1. 结论或当前决策。
2. 关键证据，最多 3 条。
3. 下一步。

不要输出完整思考过程、完整工具日志、无关背景、重复的文件内容。

## 红线

- 不要为了省 token 跳过必要验证。
- 不要压缩掉用户明确要求保留的细节。
- 不要把不确定事实写成确定结论。
- 不要用“节省 token”为理由省略安全、测试、影响面或来源证据。
- 不要在一个回复里同时解决多个未确认的大范围问题；先收敛范围。
- 不要读取未命中的技术栈模块、无关 workspace 项目或完整模板，只因为它们“可能有用”。

## 与其他技能集成

- `brainstorming`：只保留设计共识，不生成长规格。
- `gitnexus-exploring`：用知识图谱替代全仓库盲读。
- `systematic-debugging`：先定位根因，再读取相关上下文。
- `requesting-code-review`：子代理只返回阻塞问题和证据。
- `verification-before-completion`：验证输出只摘命令、退出码和关键结果。

## 完成检查

结束前确认：

- [ ] 当前回答只包含推进任务所需信息。
- [ ] 证据足够支撑结论。
- [ ] 未读取或粘贴无关大段内容。
- [ ] 下一步明确且数量不超过 3 个。
