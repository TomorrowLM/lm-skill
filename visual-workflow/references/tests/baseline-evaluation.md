# Visual Workflow 基线评估

## 范围与方法

- 评估层级：隔离场景决策；不代表自动技能路由或真实浏览器执行。
- 允许读取：Phase 4、Phase 5、`browser-verification` 和 `skill-routing` 当前规则。
- 禁止读取：Figma 实现和 frontend-design 两个目标技能正文。
- 执行者：独立基线 Agent；未修改文件。

## 观察到的失败

### 场景 A：Figma 材料先形成技术方案，再实现和验收

- 当前路径把 Figma 输入直接路由到 Figma 实现技能；Phase 4 又要求 Phase 1–3 方案和 spec 已确认。
- 允许读取的路由和阶段文件没有明确说明视觉材料如何进入技术方案及 `#10`，也没明确区分方案、实现和最终视觉验收的职责。
- 判定：**基线失败**，存在可复现的阶段交接断层。

### 场景 B：仅有截图或文字方向的视觉设计

- 路由表指向 frontend-design，但没有与页面技术方案、实现和验收清单衔接的输出约定。
- “更有辨识度”等表达也没有和 Figma 输入路由形成明确的统一入口。
- 判定：**基线失败**，视觉方向与页面工作流之间缺少约定。

### 场景 C：Phase 5 Figma 视觉对比

- Phase 5 将 Figma 对比委托给 browser-verification 的 `visual-comparison.md`；实现规则则位于独立的 Figma/frontend-design 技能。
- 因而视觉实现原则、Figma 操作流程和验收对比方法分散在多个技能与阶段文档中。
- 判定：**基线失败**，存在规则分散与职责边界不清。

## 限制

以上是当前文档路径下的场景决策基线。它不证明任何技能自动触发，也不证明页面或浏览器实际验收已执行。
