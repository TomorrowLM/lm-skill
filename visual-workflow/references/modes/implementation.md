# 模式：视觉实现

## 前置条件

优先使用已确认的技术方案、spec 和 `#10`。用户直接要求实现单个视觉组件时，按用户授权范围执行，不因此强行启动完整页面工作流；页面级开发仍遵循 `page-development-workflow` Phase 4 门禁。

## Figma 工作流

1. 从 Figma URL 提取 fileKey 和 nodeId；使用 `figma-desktop` MCP 时可读取当前选中节点，不伪造 URL 或 fileKey。
2. 通过 Figma MCP 获取节点 `get_design_context` 和同一节点的 `get_screenshot`；响应截断时先用 `get_metadata` 找主要子节点，再分区取上下文。截图保持可访问，作为本轮参考依据。
3. 按需下载实际资源。Figma MCP 为图片或 SVG 返回可用的 localhost 来源时直接使用，不修改来源、不造占位图，也不为替代资源新增图标包。
4. 页面工作流中的参考截图、标注和下载资源存到当前功能目录的 `assets/figma/`；技术调研模式只查看、不下载或落盘。`download_figma_images.localPath` 也必须指向该目录。
5. 将 Figma 输出视为设计和行为表达，不当作项目最终代码。检查现有路由、组件、样式、状态和请求模式；映射到项目设计令牌与可复用组件后再实现。
6. 逐区域实现布局、排版、资源和设计明确的状态。增量自查用于发现差异，但不能替代 Phase 5 正式验收。
7. 若设计系统、可访问性或已确认业务规则与视觉稿冲突，暂停破坏性取舍并请求确认；获准偏差记录在技术方案/执行结果中，不把临时 Figma 节点信息写入源码注释。

## 非 Figma 视觉实现

没有 Figma 时，先从已确认的技术方案或视觉 brief 提取主题、受众、页面任务和未覆盖决策。只有获准的视觉自由度才由本模式定方向；按 `visual-standards.md` 提出有根据的色彩、排版、布局、内容和动效方案，确认方向后再写代码。页面必须适配实际业务信息和项目约定，不用通用视觉模板替代需求。

## 收口

实现完成只报告代码改动、自查范围和未验证项。不得仅凭 Figma 截图、源码、局部对比或“接近”宣称 1:1 通过；正式视觉与业务验收由 Phase 5 执行。
