# 模式：视觉材料到技术方案

## 输入与输出

输入可以是 Figma URL/节点、截图、原型、标注、PRD 或视觉方向描述。输出应进入主工作流的技术方案和 `#10 测试用例与验收清单`，包含页面结构、主要状态、交互、视觉约束、资源定位、待确认项及验收方式。文档排版由 `writing-doc` 负责。

## 执行步骤

1. 确认材料来源、页面范围、目标用户和本次决策；信息缺失时列问题，不补造事实。
2. 有 Figma 输入时解析 fileKey/nodeId，使用 `mcp-exe` 调用可用的 Figma MCP 获取设计上下文和对应截图。响应过大时先取 metadata，再按主要区域分批获取上下文。只读调研阶段不下载资源、不写代码。
3. 非 Figma 图片只使用用户提供的文件或获准图像分析能力。区分看得见的结构/文案与无法从图片确认的交互、断点、接口和状态。
4. 建立页面区域和组件层级，记录尺寸/间距/字体/颜色/状态等设计证据；设计数字缺少适配依据时保留原值并标注待确认，不猜换算。
5. 对照现有路由、组件、样式、请求和设计系统，形成复用边界、差异、技术风险和资源计划。
6. 将视觉验收项写入 `#10`，同时明确业务流程验收项；图片中未确认的内容不能变成业务验收标准。
7. 展示方案、假设、待决策点并等待用户确认。没有确认时停留在方案阶段。

## 视觉方向未定义时

仅当材料/brief 留有视觉决策空间时执行；已有 Figma 或品牌规范已确定方向时不另造方向。

1. 明确页面主题、目标用户和页面单一任务。
2. 提出有实质差异的视觉方向；每个方向说明依据，并给出 4–6 个命名色值、展示/正文/数据字体角色、布局概念和一个适合业务的识别特征，必要时用简短线框比较。
3. 对照业务、项目设计系统和常见模板套路自我审查，检查方案是否只是通用模板变体；说明取舍，再交用户确认。
4. 未确认前不把个人审美选择写成既定需求，也不开始相应代码实现。

## Phase 边界

`page-development-workflow` Phase 1 使用本模式的只读调研部分：获取上下文、截图和结构摘要，不落盘 Figma 资源、不创建实现代码。Phase 2 依据已确认调研编写技术方案。进入 Phase 3/4 仍需遵守主工作流各自的确认与入口自检。
