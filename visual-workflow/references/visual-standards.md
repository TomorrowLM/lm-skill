# Visual Standards

本文件是三个模式共用的视觉标准；模式文件只补充当前阶段的操作流程，不重复定义这些规则。

## 来源与优先级

1. 已确认的用户需求、技术方案和 `#10` 验收项定义功能范围与业务预期。
2. 项目现有组件、设计系统、适配方式和代码约定是实现基线。
3. Figma、原型、截图和标注提供其实际覆盖到的视觉与交互信息。
4. 通用视觉建议只填补前三者未覆盖的决策，不得推翻已确认要求。

来源冲突时先标出差异与影响，再请求确认；不能通过“尽量还原”静默改变业务或项目约定。

## 设计方向

- 从产品主题、目标用户和页面任务提炼视觉方向。没有既定设计时，选择有依据、适合业务的排版、色彩、层级和布局，不套用无关模板。
- 字体、颜色、间距、圆角、图标和动效应形成一致体系；需要展示型、正文或数据文字时分别选择清晰的字体角色；复用项目令牌和组件，避免为追求像素相似重复造已有能力。
- 结构表达信息关系，装饰和动效必须服务于内容、导航或反馈；删去不承载意义的装饰。
- 页面层级、编号、分隔线和标签应表达真实的信息关系，不为装饰机械添加序号；着陆页或品牌页首屏是否突出主体，服从页面目标和已确认方向。
- 新方向应体现具体业务与受众，不默认套用常见奶油色衬线、黑底荧光色或报纸网格等通用视觉套路；单一醒目元素只有在适合场景且有依据时才采用。
- 已有视觉 brief、Figma、品牌规范或项目设计系统时以其为准，不为了“差异化”强行换风格；未指定方向时才提出有依据的探索方案。
- 文案从使用者视角表达，控件动作、错误和空状态清晰一致，不以营销性描述替代可操作信息。
- 视觉复杂度匹配已确认方向：复杂方向需要完整执行，克制方向则以排版、间距和状态细节见质量；减少无助于任务的装饰和零散动效。

## 还原与实现

- Figma 数值先确认节点、单位和项目适配比例，再映射成项目中的 CSS/设计令牌；不得凭截图宽度推断 DPR、视口或换算比例。
- 检查父容器与子元素的 padding、gap、margin、背景和资源内置底色，避免重复留白、叠加背景或擅加卡片容器。
- 使用与设计匹配的资源；核对图片、图标的来源、透明区域、展示尺寸和裁切方式。不得用相似占位资源冒充设计资源。
- 覆盖设计涉及的桌面/移动视口、文本长度和交互状态；确保内容不溢出、不遮挡，键盘焦点可见，并尊重减少动态效果设置。
- 自查桌面视口下的关键布局、内容和交互状态；发现偏差时先判断是否符合已确认方向与项目约定，再记录待修复或待确认项。
- 为可访问性、技术限制或项目系统而偏离视觉稿时，在技术方案或验证证据中说明原因、影响和实际处理；不把临时任务节点号写进源码注释。

## 对比与证据

- 比较前固定设计版本、节点、页面来源、业务记录/Tab/弹层状态、视口、缩放、DPR 和滚动位置；不可比项只报告可比较部分。
- 分开记录设计原值、源码声明和工具实际测量。工具没有 computed style 或布局测量能力时写“未测量”，不从 className、截图像素或目测编造实际 CSS。
- 以整页模块关系为背景逐模块对比，最后复查共享边界、相邻间距、固定区域、安全区和遮挡。局部通过不能推导整页通过。
- 不输出无可复现算法与输入的相似度百分比。每项结论限定到证据覆盖范围，并标记通过、失败、未验证、阻塞或不适用。
- 截图用于发现视觉候选，不替代 DOM、交互和业务状态证据；实际浏览器取证按 `browser-verification` 执行。
