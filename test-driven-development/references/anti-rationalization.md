# 防绕过与范围失控

**在考虑跳过红绿，或不确定测试范围时加载。**

| 想法 | 正确动作 |
| --- | --- |
| “改动很简单，赶时间，先改再测。” | 保留红绿顺序，把范围缩到一个聚焦行为测试。 |
| “多写几组测试更保险。” | 先覆盖目标行为和有区别的边界；仅为独立行为或实质风险增加测试。 |
| “每个断言都要跑完整测试套件。” | 红绿阶段跑最窄相关命令；更广回归仅在收尾按需执行。 |
| “没有 test 脚本，装个框架再说。” | 先找现有 runner 或项目命令；不要为单次改动新增基础设施。无法执行时报告阻塞。 |
| “我已经手动测过了。” | 手动检查不能替代可重复的红绿证据。 |
| “测试先通过了，说明实现正确。” | 确认测试能区分新旧行为；不能区分就调整测试，不把立即通过当红灯。 |

快路径只减少测试数量和运行范围，不取消行为变更的失败证据或绿灯验证。
