# 微前端基座规范

## 核心原则

父应用只完成子应用注册、挂载和路由匹配；子应用负责自身路由、状态和接口逻辑。

## 子应用注册

- 子应用列表由 `VITE_MICRO_APPS` 控制，值使用稳定业务子应用编码
- 未配置的子应用不注册、不参与路由匹配
- 子应用 `entry` 由 `{VITE_WEB_ORIGIN}{ENTRY_PATH}/` 派生
- `activeRule` 直接使用对应 `ROUTE_PREFIX`
- 子应用独立部署入口 path 和基座内路由前缀分别从环境变量读取，不允许用一个变量同时表达两种含义

## 部署约束

- 父应用与子应用按同产品线、同域名、同环境部署
- 不加载跨域子应用
- 不设计 qiankun props 通信契约

## 菜单与路由

- 菜单数据以后端返回的当前用户可用菜单树为准
- `resourceKey` 作为前端路由资源标识
- 父应用根据 `resourceKey` 判断目标子应用
- 菜单选中态、展开态由当前路由反推
- 菜单转换、路由匹配、子应用匹配逻辑需要保持为独立纯函数，并补单测
