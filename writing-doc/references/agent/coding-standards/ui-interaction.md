# UI 与交互规范

## 状态展示

1. 组件和页面需覆盖加载、空、错误、成功等用户可感知状态
2. 加载状态需区分首次加载、局部加载和提交中，避免使用全屏状态遮挡无关内容
3. 空状态需说明当前无数据或无匹配结果，并提供必要的下一步操作
4. 错误状态需提供明确反馈和可行的重试入口

## 操作反馈

1. 成功、失败和进行中状态需与用户操作保持一致，避免无反馈或重复反馈

## 提交与危险操作

1. 提交类交互需在请求处理中禁用相关操作，防止重复提交
2. 删除、撤销或其他不可逆操作必须进行二次确认，并明确说明操作影响
3. 操作失败后应恢复可操作状态，避免页面停留在不可提交状态

## 图片展示

1. 业务内容图片和图片附件必须支持点击预览，纯装饰图、图标和背景图不强制预览
2. 优先使用项目已有的 `FileView` 或 `ImagePreview` 组件；不存在时使用当前 UI 库的预览能力，不重复封装同类组件
3. 内容图片必须提供有意义的 `alt`，纯装饰图片使用空 `alt`，避免重复朗读无业务信息
4. 图片加载失败需显示兜底占位图，不展示裂图

## 可操作元素

1. 输入框、按钮等可操作元素按项目测试规范添加测试标识
2. 不可操作状态需通过禁用、只读或明确提示表达，不能仅依赖颜色区分
