# 通用规范

## 编码约束

### 核心原则

- 先约束再实现：写代码前明确规范边界，不要写完再补规范
- 自动化优先于文档：没有 lint/format/CI 强制执行的规范只是建议
- 不只盯格式：还要覆盖结构、复用边界、耦合和性能
- 遗留项目渐进收敛：先硬规则后软规则、先核心模块后边缘模块

### 红线

- 不写无注释函数，尤其是业务函数、工具函数和组件方法
- 不只有规范文档而缺少 lint/format/CI 强制执行
- 不在遗留项目里一次性强推全部规则
- 不把规范工作缩减成纯格式化问题
- 不忽略组件封装、复用和架构边界
- 不在框架或技术栈升级后长期放任规范过期
- 业务逻辑避免副作用，优先抽取可复用纯逻辑
- 不新增无必要第三方依赖
- 有业务语义的数字必须提取为枚举或具名常量，禁止在组件、服务和工具函数中散落魔数
- 项目已配置路径别名时，优先使用别名导入，禁止使用可被别名替代的跨目录相对路径

---

## 业务约定

> 通用规范与项目业务约定冲突时，以项目业务约定为准。

1. 数据为空时用 `--` 表示
2. 接口请求失败提示由请求层统一处理，业务代码不自行定义重复提示

## 注释规范

1. 文件注释（文件最前面）：
   ```javascript
   /**
    * @author : 作者
    * @date : 时间
    * @module : 模块名
    * @description : 模块描述
    * @version : 版本号
    */
   ```
2. 单行注释：`// `（注释符后加空格）
3. 多行注释：`/* ... */`（结束符前留空格）
4. TODO 标记：未实现功能必须标注，例：`// TODO 未处理分页`
5. 文档注释：
   ```javascript
   /**
    * 方法说明
    * @method 方法名
    * @for 所属类名
    * @param {类型} 参数名 参数说明
    * @return {类型} 返回值说明
    */
   ```

## 封装规则

### 组件封装

1. 组件只封装稳定 UI 单元或复用业务块，单页面少量代码不单独抽组件
2. React 组件使用 PascalCase，组件默认导出，类型和工具函数命名导出

### 目录归属

1. 页面私有组件、hooks、utils、consts 放在页面目录
2. 跨页面复用组件、hooks、utils、constants 才放公共目录

### utils 规则

1. utils 只放可复用纯逻辑
2. utils 不放 JSX、请求副作用或页面私有状态

### 常量与枚举规则

1. 跨模块数字枚举放 `src/enums/`，按业务领域拆分文件
2. 跨模块状态值、选项配置、颜色映射等常量放 `src/constants/`
3. 页面私有数字枚举放页面 `enums.ts`，页面私有选项、阈值和展示常量放页面 `consts.ts`
4. 禁止在业务代码中散落状态、等级、类型等魔数。

### 引用与定义注释要求

1. 能使用项目路径别名时，统一使用别名引用模块；相对路径仅用于别名无法覆盖的同级局部引用
2. 枚举、类型、函数和重要变量必须添加中文注释，说明业务含义或使用边界
3. 字段注释应说明数据来源、业务语义或特殊取值，不能只重复字段名称
