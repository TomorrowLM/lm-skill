### 指标 4：Token 成本评估

#### 4.1 简单列表页场景
- 用户需求：新建列表页，包含搜索、排序、分页
- 加载内容：SKILL.md (69 行) + 不加载 reference

**对比观察**（定性）：
- 改写前：表格形式冗长，AI 会预读所有 6 个 Phase reference 定义
- 改写后：3 列快速表 + 指向 reference，AI 可快速定位到 Phase 1-2，不预读无关 reference

**估算**：
- SKILL.md 本体：~1200 token
- 不加载其他文件：节省 ~1500-2000 token（相比预读所有 reference）
- 净收益：~30-40% token 减少

#### 4.2 复杂多模块场景
- 用户需求：5 个页面 + 多接口 + 并行编码
- 加载内容：SKILL.md (69) + Phase 4 部分 (phase4-execution-modes.md) + 新增 execution-patterns.md (94)

**对比观察**（定性）：
- 改写前：Phase 4 混含了隔离执行的长段落（200+ 行），简单任务也要读
- 改写后：Phase 4 保持轻量，隔离执行单独为 guide（94 行），仅需要时加载

**估算**：
- SKILL.md：~1200 token
- execution-patterns.md：~1400 token
- 总计：~2600 token

| 场景 | 内容 | 改写前 token 估算 | 改写后 token 估算 | 节省比例 |
|------|------|----------|----------|----------|
| 简单列表页 | SKILL.md + 不必要的所有 reference | ~3500 | ~1200 | ↓ 66% |
| 复杂多模块 | SKILL.md + execution-patterns.md | ~2800 | ~2600 | ↓ 7% |

**结论**：✓ 可接受 — 简单场景大幅减少，复杂场景成本合理。总体 token 效率提升。
