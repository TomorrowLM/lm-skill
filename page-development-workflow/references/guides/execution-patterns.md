# 隔离执行与设计资源管理

仅在使用 MCP、多窗口、子代理或有大量设计资源时读取。简单内联任务可忽略本文。

## 设计资源职责划分

### Phase 1：主窗口调研阶段
- 主窗口读取 Figma、截图、UI 原型，用于理解需求、定位资源。
- 不做完整视觉分析，只提取业务流程、边界条件、组件清单。
- 设计资源定位和版本号写入 Phase 1 确认文档。

### Phase 3：规划阶段
- Phase 3 拆分方案中仅记录"涉及的 Figma 页面""资源路径"；不重复打开。
- 用户选择方案后，隔离执行任务根据资源定位自行调用 Figma 或图片分析。

### Phase 4-5：执行与验收
- **内联任务**（简单页面、单模块）：由当前窗口继续读取设计资源实现。
- **隔离任务**（复杂多窗口、MCP 编排）：新开执行任务根据资源定位自行调用 Figma MCP、图片分析能力，获取实现所需详情，并将 Figma 资源保存到 `assets/figma/`。
- **验收截图**：不是设计参考，Phase 5 验收子窗口独立生成页面截图并保存到 `assets/screenshots/`；主窗口审查时按需读取，不重新执行完整浏览器验收。

## 隔离执行（多窗口/MCP/子代理）规则

适用场景：计划明确为"并行任务""子任务编排"或预期代码变更大于 500 行。

### 主窗口职责
- 负责 Phase 1-3：调研、方案、计划确认。
- Phase 4 入口自检完成后，生成每个子任务的独立 `spec/NNx-<module>-spec.md`。
- 每个 spec 包含：
  - **任务边界**：修改的文件清单、不修改的依赖。
  - **验收标准**：本子任务的成功标准（功能点、测试通过、浏览器验收项）。
  - **设计资源定位**：Figma URL、截图路径、OpenAPI 文档版本（可选）。
  - **隔离技能列表**：本子任务需要的技能（如 test-driven-development、browser-verification 等）；无则写"无"。
- 并行批次执行后，主窗口负责合流检查、冲突合并、跨任务验证。
- 最终汇总为 Phase 5 验收。

### 子任务职责
- 加载 spec 中列出的技能，不加载不在清单中的技能。
- 根据设计资源定位自行读取 Figma、图片、API 文档，不返回完整网页内容或图片数据。
- 实现、测试、局部验证都在隔离窗口完成。
- 返回结果只包含：修改的文件清单、修改摘要、验证结果、关键资源路径、遗留问题。
- 返工任务：返工文档自包含具体修改内容和原因，无需重新阅读原 spec。

### 返工文件格式
```markdown
## 返工原因
[简述 Phase 5 验收或代码审查发现的问题]

## 待改文件
- `src/pages/xxx/index.tsx`（变更理由：...）
- `src/services/xxx.ts`（变更理由：...）

## 需要的技能
test-driven-development、browser-verification

## 验收目标
[重新通过 Phase 5 验收的具体条件]
```

## 子任务规格模板

```markdown
# NNx-<module>-spec

## 任务边界
- **修改文件**：`src/pages/xxx/`, `src/services/xxx/`
- **不修改**：公共组件库、全局状态、路由配置

## 验收标准
- 功能 1：API 请求成功且响应字段映射正确
- 功能 2：表格分页、搜索、排序工作正常
- 功能 3：浏览器验收：列表页渲染无报错，加载态正常
- 测试：`pnpm run test *.test.tsx` 全部通过

## 设计资源
- Figma：`https://figma.com/...` （最后更新 2026-08-29）
- 截图：`assets/figma/list-page-ui.png`
- API：POST `/api/list`, 见 Swagger 地址

## 隔离技能清单
- test-driven-development
- browser-verification

## 约束
- 不得修改 `src/constants/` 的已有常量（除非用户授权）
- 新增类型必须放在 `src/services/XxxService/types.ts`
- 不得修改全局 CSS；页面私有样式放 `index.module.less`
```

## Token 效率建议

- Figma 和大图片由隔离任务读取，主窗口仅保存路径引用。
- 返工文件改短：只列修改内容和原因，不复述原 spec。
- 多窗口验收时，Phase 5 验收子窗口的截图和测试输出保存到文件系统，主窗口通过文件路径引用而不是粘贴输出。
- 合流时主窗口只检查关键结论和修改清单，无需重新阅读完整实现细节。
