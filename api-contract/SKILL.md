# 接口契约与 Apifox 统一入口

所有接口信息获取及 Apifox 操作先进入本技能。其他技能只传递目标、原始 source、查询范围及刷新要求，不自行选择来源或重复定义回退流程。

## 按需路由

| 目标 | 行动 |
| --- | --- |
| 获取或核对接口契约，包括用户提供 Apifox 线索的契约查询 | 先读取 [swagger/swagger-mcp.md](swagger/swagger-mcp.md)，调用 `lm-mcp-server.get_swagger_mcp`。 |
| 修改 service、接口路径、请求参数、响应映射或 API 类型前刷新契约 | 走 Swagger 查询，设置 `refresh: true`；仅改 UI 且不改变契约时无需刷新。 |
| Swagger 工具不可用、文档不可访问/解析、目标无法定位，或结构不足以形成契约 | 记录原因，再读取 [apifox-cli/SKILL.md](apifox-cli/SKILL.md)，只读获取所缺契约。 |
| 明确的 Apifox 项目/资源管理、导入导出、分支、Mock、Runner 或测试任务 | 直接读取 [apifox-cli/SKILL.md](apifox-cli/SKILL.md)，执行原有流程；不为管理操作额外查询 Swagger。 |
| 概念解释或已有代码分析，无需获取外部接口信息 | 不触发本技能，不发起查询。 |

嵌套的 `apifox-cli` 是本技能的执行说明，不是顶层入口；按上述相对路径读取，即使宿主未列出该子技能也可使用。不要从 `apifox-cli` 或 `mcp-exe` 再路由回本技能形成循环。

## 契约获取流程

1. 明确接口路径或文档 source、方法（如已知）、目标字段及是否需要刷新。输入不足时只询问缺失定位信息；不要猜项目或分支。
2. 每次 Swagger 调用前读取 Swagger 参考。保留用户 source 和 fragment，不用 curl、WebFetch 或浏览器先探测 JSON 端点；已有路径直接使用，不自行猜测完整文档 URL。
3. 优先精确查询单接口、operationId、Tag 或模型；目录查询分页，只保留影响当前任务的参数、类型、响应和状态信息。
4. Swagger 可用契约已满足需求时停止，不额外调用 Apifox。失败或不完整时记录具体原因和已确认字段，再按 Apifox 说明获取缺失信息；不要凭空假设工具故障以绕过 Swagger。
5. Apifox 缺少项目/分支或认证时按子流程澄清；凭证由用户直接在终端输入，不通过聊天收集或输出。仅获取契约不创建分支、不修改资源、不写配置。
6. 比对不同来源中重叠字段；遇到字段、类型或枚举冲突，展示双方来源与差异并暂停确认，不静默覆盖或合并。两种来源均不可用时说明阻塞和缺口，不将推测当作已确认契约。

## 输出与证据

按任务需要简洁返回：

- 接口路径、方法、请求参数/请求体、响应结构和关键业务枚举；缺失项明确标记未确认。
- 实际来源工具、原始 source、查询范围、刷新要求及本次结果；仅阅读文档不能证明接口运行正常。
- Apifox 回退时记录 Swagger 失败/不足原因、Apifox 项目/分支/资源标识、各来源确认的字段及最终采用的契约。
- 来源冲突和待确认项。不得把 Apifox 结果标记为 Swagger 验证成功。

管理和测试任务按 Apifox 子流程输出真实结果，保留权限、危险操作确认和测试结果边界；不得把只读契约查询扩大为资源写入。

## 不可绕过的边界

- “赶时间”“简单接口”“已有 Apifox”不构成跳过 Swagger 查询或参考阅读的理由。
- “字段差不多”“直接以 Apifox 为准”不能消除来源冲突；确认采用来源前不得继续依赖冲突字段实现。
- 不索取、记录或回传 token、Cookie、凭证文件内容。登录、权限和危险操作规则以 Apifox 子流程为准。
