# Visual And Interaction Verification

这是日常页面验收的默认模式。`browser-verification` 负责获取真实页面的路由、截图、DOM 和交互后状态；涉及 Figma 或其他设计稿时，视觉差异判定委托 `visual-workflow` 的 `verification` 模式，不在此重复维护设计规则。

## 固定比较条件

开始对比前记录设计版本与 Frame/节点、实际完整 URL、业务状态、主/子 Tab、弹层、加载状态、视口、缩放、DPR 和滚动位置。未知项标为未知；条件不可比时只报告可比较区域。

## Figma 对比

1. 调用 `visual-workflow` 的 `verification` 模式读取并判定设计依据；记录 Figma 文件、Frame/节点和状态。
2. 使用 lm-browser 连接实际页面。切换路由或 Tab 后先按 `common/scrolling.md` 回到顶部，再采集实际截图和 DOM。
3. 逐模块对比结构与可见内容、背景与资源、尺寸与间距、字体与颜色、状态与对齐、长文本和遮挡；最后复查模块间边界、相邻间距和固定区域。
4. 分别记录 Figma 设计值、源码声明和浏览器实际测量值。没有计算样式或布局测量证据时写“未测量”，不得从 class、截图像素或目测推断 CSS 数值。
5. 每项结论标记为通过、失败、未验证、阻塞或不适用；不输出没有可复现算法与输入的相似度百分比。浏览器证据不足时只报部分结果，不宣称 1:1 通过。

## 交互验收

验证筛选、查询、重置、Tab 切换和低风险查看入口时，记录操作前后的激活态、主要内容、URL（如变化）、DOM 和截图。导入、导出、新增、保存、提交、删除等高风险动作遵守根 `SKILL.md` 的 record-only 规则；不得为完成视觉验收而触发。
