# 按模块进行设计还原对比

适用于 Figma、设计图与实际页面的视觉对比；业务流程单独验收。只要求截图分析时，使用现有图片，不操作浏览器、不修改代码，并明确结论仅覆盖截图。

## 1. 固定比较条件

- 记录设计版本、Frame/节点、页面来源和截图路径。实际页面同时记录完整 URL、业务记录、主/子 Tab、弹层、加载状态及滚动位置；URL 相同不代表实际任务或组件状态相同。
- 记录视口、浏览器缩放、DPR 和设计尺寸；未知项标记未知，不从图片宽度推断实际 CSS 视口或 DPR。不同状态、视口或缩放先对齐；无法对齐时只比较可比模块，不能把前后图片当作修复通过证据。
- 已确认的需求变更列为排除项。动态名称、数量、风险状态不直接判错，但仍要检查长文本、三位数徽标等边界布局。
- 截图裁切、选中高亮、调试面板、悬浮控件和登录空态单独记录；未确认来源前不得归咎业务 CSS。图片不可读时只报告阻塞，不生成差异。

## 2. 先整页建图，再逐个模块闭环

1. **整页建图**：按业务职责和视觉边界列出模块顺序、父子关系、共享容器和固定区域，不按每个 DOM 节点机械拆分。例如企业信息、快捷工具、二级 Tab、任务摘要、结果列表和底栏。
2. **逐个模块对比**：保持整页上下文，自上而下处理一个模块；逐项记录设计期望、实际观察、证据、差异和结果，再进入下一模块。完整截图用于定位，局部截图用于细看；工具不支持裁切时沿用整图区域定位，不伪称已生成局部截图。
3. **先结构后细节**：每个模块先检查容器、顺序与可见内容，再核对背景、资源、尺寸、间距、字体、颜色和对齐。设计中的无独立填充容器不能擅自套成白色圆角卡；沿用哪个背景仍需核对父容器。
4. **未解决项保留**：单模块失败或阻塞进入差异台账。诊断其余独立模块可以继续，但不扩大通过范围；不得等用户再次指出才检查未完成模块。
5. **模块间回归**：最后重看整页的共享左右边界、相邻间距、纵向节奏、固定底栏、安全区和遮挡。局部通过不能代替整页通过；只要求局部分析时明确整页未验证。

## 3. 每个模块必查的证据

| 维度 | 核查方法 |
| --- | --- |
| 背景与容器 | 分清页面底色、模块填充、圆角、边框、阴影及父子 padding；不要将“企业信息卡”等组件名当成白卡设计依据 |
| 图片与图标 | 核对资源节点、实际文件、内置底色/渐变、透明区域、viewBox、展示尺寸及 object-fit；资源自带底色时不额外叠底，不用相似图标冒充原图 |
| 尺寸与间距 | 先读取项目适配规则和对应节点/模板，再记录设计原值、转换依据与目标 CSS 值；没有依据不机械除以二。将父 padding、父 gap、子 margin 和控件内部留白分开计算 |
| Tab 与状态 | 分别检查容器宽高、padding、单项高度、字体、圆角、阴影、选中/未选中态；减少 Tab 数量后重新核对布局，不恢复已排除项 |
| 文本与边界 | 检查字号、字重、行高、长标题换行/截断、按钮独立空间、数量徽标和图文对齐，动态内容不同不等于布局正确 |

- **设计数字有来源才使用**：例如已确认 750 设计映射至 375 CSS 视口，节点图标 48 对应 24、Tab 高度 57 对应 28.5；不能先凭印象改为 32 再补依据。描边、阴影、位图导出倍率和 DPR 按各自语义处理，不能一起套比例。
- **分开设计值、源码值和实际值**：截图支持可见差异，源码支持实现定位；className、内联声明或“看着差不多”不是 computed style。只有当前获准工具确实提供计算样式/布局测量时才记录实际数值，否则标记未测量。
- **视觉模型只提供候选**：逐项复核截图和需求排除项，丢弃无证据的差异、虚构测量及没有客观算法和输入记录的“还原度百分比”。

## 4. 输出与修复边界

每项视觉检查使用通过、失败、未验证、阻塞或不适用，结论只覆盖对应证据。至少记录：模块、属性、设计依据、实际观察/测量、证据路径、差异、结论及下一步；实际值未知时保留未知。

模块对比表必须有独立的“结果”列，填写上述状态，不能用“建议调整”或“结构接近”代替判定。同一模块既有可确认差异又有未测量属性时分行记录，不能用模块整体通过覆盖未知项。

例如：企业信息容器的设计为无独立填充、实际截图为白色圆角面板，应明确记录“额外背景与包裹”，不能只说“弱化边界”。如果背景来源尚未定位，先记录差异与待查项，不直接猜 CSS 修复。

- 报告分别列出**设计还原结果**与**业务流程结果**；Figma 可以提供交互线索，不能替代已确认的业务规则。按钮存在不代表流程通过，组件名/setter 名不是操作后证据。
- 只做视觉分析时不点击保存、提交等操作，不为满足交互 verified 门禁扩大范围；视觉检查项通过不等于交互节点 `verified`。静态分析不得宣称真实页面或业务流程已验证。
- 用户批准修复后，每次处理一个模块的最小改动，先运行对应检查再继续。修复后复采同一模块、父容器及受影响邻接区域；最后做整页回归。批准的同一范围内不重复发起需求访谈，新增范围或标准冲突才询问。
- 无浏览器、只完成代码检查或资源导出时，记录“已修改，视觉未验证”。代码 lint、依赖解析阻塞的类型检查和旧构建结果不能代替截图验收。
