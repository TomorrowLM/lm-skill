# 重复模板与代表性抽样协议

本文件适用于所有浏览器验证模式。目标是避免对完全相同的模板重复递归，同时保留所有实例的发现、差异识别和覆盖证据。

## 1. 可以归为同一模板的条件

只有同时满足以下条件，才可以归为同一模板：

- DOM/组件结构、主要语义和定位方式一致。
- 交互动作、后续状态、路由和覆盖层行为一致。
- 权限、风险等级和可执行策略一致。
- 不存在独特的 Tab、Tooltip、链接、按钮、字段、错误态或数据依赖行为。

仅仅“截图长得像”不足以证明同模板；需要截图、DOM 和适用的 MCP 状态证据共同确认。

## 2. 固定流程

1. 先枚举当前范围内全部重复候选，保留每个实例的 `id`、定位、标题/文本、父节点和 occurrence。
2. 按模板、变体和状态分组；发现标题、权限、交互、路由、数据状态或子控件差异时拆组。滚动到后续区域时，优先将新候选与已确认模板比对。
3. 每个模板选择代表实例；优先覆盖首个、中间、末个，或覆盖不同可见状态的实例。
4. 只对代表实例执行完整的截图 → DOM → MCP 操作后状态闭环；其余实例做结构和差异核对，不重复执行相同递归。
5. 记录模板覆盖范围和未抽样原因；代表实例证据只能证明模板行为，不自动证明每个实例都可交互。

滚动发现已确认模板的新实例时，可以记录 `covered-by-template` 并继续下一个区域；这只是跳过重复结构解析，不是跳过实例发现、差异检查或必要的数据记录。

## 3. 仪表盘卡片示例

多个“数量 + 百分比进度条 + 已/未状态行”的统计卡片，可以抽取一个 `metric-card` 模板，记录所有卡片标题、定位和数量。带 Tooltip、Tab 切换、点击跳转或不同状态结构的卡片属于变体，需要额外抽样验证；不必把每张相同卡片都展开成独立的完整控件树。

## 4. 输出要求

```text
templateId, representativeId, instanceIds, instanceCount,
variantIds, coverage, representativeEvidence, status, reason
```

同模板未抽样实例使用 `covered-by-template`/`partial` 等明确状态，不得伪装成逐实例 `verified`。任何实例出现未解释差异时，模板组不能标记为完整验证。
